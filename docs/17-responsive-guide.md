# مزرعة بيتنا — دليل الـ Responsive
## الموقع يشتغل صح على كل التليفونات

---

## الفكرة الأساسية أولاً

**الـ 393px مش عرض الموقع — ده عرض لوحة التصميم في Figma.**

إنت صمّمت على مقاس iPhone 14/15 Pro عشان تشوف الشاشة كأنها في تليفون. لكن الموقع الحقيقي **مالوش عرض ثابت** — بياخد عرض الشاشة اللي شغال عليها.

**المشكلة:** الأكواد اللي بتطلع من Figma فيها أرقام ثابتة زي `width: 345px`. لو نفّذتها كده، على تليفون عرضه 360px هتلاقي عناصر بتطلع بره الشاشة أو scroll أفقي.

**الحل:** تستبدل الأرقام الثابتة بمرونة — العنصر ياخد المتاح بدل ما ياخد رقم محدّد.

---

## الأرقام اللي تهمك

| العرض | الأجهزة | نسبة الاستخدام |
|---|---|---|
| **320px** | iPhone SE قديم | نادر — بس اختبر عليه |
| **360px** | أغلب أندرويد المتوسط والرخيص | **الأكثر انتشاراً عالمياً** |
| **375px** | iPhone SE / 12 mini | شائع |
| **390–393px** | iPhone 14/15/16 · Pixel | **تصميمك اتعمل هنا** |
| **412–430px** | أندرويد كبير · iPhone Pro Max | شائع |

> **٣٦٠ و٣٧٥ مع بعض = أكتر من نص الزيارات عالمياً.** وعملاؤك في مصر غالبيتهم على أندرويد متوسط — يعني **360px هو الحالة الأهم عندك**، مش 393.

**القاعدة:** الموقع لازم يشتغل صح من **320px** لحد **430px+**.

---

## القواعد العملية

### ١. حوّل العرض الثابت لمرن

```
❌ width: 345px
✅ w-full  (جوّه حاوية عندها px-6)
```

345 + (24 × 2) = 393. يعني `345px` هي "عرض الشاشة ناقص الـ padding". لو خليتها `w-full` جوّه حاوية بـ `padding: 24px`، هتشتغل على أي عرض.

### ٢. سيب الارتفاع للمحتوى

```
❌ height: 852px  (ارتفاع الشاشة في Figma)
✅ min-h-screen
```

الارتفاعات الثابتة بتقطع المحتوى على شاشات قصيرة.

### ٣. الحاجات اللي **تفضل** ثابتة

- **أزرار الوزن: 44px** — مقاس اللمس الآمن، ماينفعش يصغر
- **الأيقونات:** 24px / 32px
- **سُمك الحدود والـ radius**

### ٤. استخدم `gap` مش مسافات ثابتة

```
❌ margin-left: 16px على كل عنصر
✅ flex gap-4  على الحاوية
```

### ٤ب. بادينج الشاشة = توكن واحد `px-screen`

بادينج جوانب الشاشة **مايبقاش رقم ثابت** — بيصغّر على التليفونات الأصغر عشان الصفوف
اللي قريبة من العرض الكامل (زي صناديق العدّاد) تفضل جوّه الشاشة من غير overflow.
معرّف مرة واحدة في `globals.css` عبر المتغيّر `--screen-pad`:

```
≥ 390px → 24px   ·   375–389px → 20px   ·   < 375px → 16px
```

```
❌ px-6  على حاوية الشاشة
✅ px-screen  (utility في globals.css)
```

لو حبينا نغيّر القيَم بعدين، نغيّرها في مكان واحد. البديل الأنعم (لو عايزين تدرّج
سلس من غير قفزات) هو `clamp()` بدل الـ ٣ خطوات.

### ٥. النصوص الطويلة

الأسماء العربية بتطول. استخدم `truncate` أو `line-clamp-2` بدل ما تحدّد عرض ثابت للنص.

## 🔴 النقاط الحرجة في مشروعك تحديداً

دي الأماكن اللي هتبوظ الأول على شاشة صغيرة:

### ١. شبكة العلف (٤٠ مربع) — الأخطر
**المشكلة:** ١٠ مربعات × 30px + ٩ مسافات × 5px = **345px** بالظبط. على شاشة 360 بعد الـ padding (24×2 = 48)، المتاح **312px** — يعني **هتطلع بره**.

**الحل:**
```
grid grid-cols-10 gap-1
مع المربع: aspect-square w-full
```
كده المربع بياخد عرضه من الشبكة نفسها، ويصغر تلقائياً على الشاشات الصغيرة.

### ٢. صف الوزن في شاشة الوزن
فيه: رقم + زر (−) 44px + الوزن + زر (+) 44px + "كجم". دول مع بعض ممكن يزحموا على 320px.

**الحل:** الأزرار تفضل 44px ثابتة، والمساحة بينهم `flex-1` تتمدّد وتنكمش.

### ٣. تبويبات الطلبات (٣ تبويبات + عدّادات)
"المكتملة ٢٣ · قيد التشغيل ٥ · الجديدة ٢٢" — على 320px ممكن تتزنق.

**الحل:** `flex` مع `gap` مرن، أو تصغير الخط درجة على الشاشات الصغيرة.

### ٤. جدول الأوزان في الفاتورة
٤ أعمدة (# · الوزن · السعر · التنظيف) بعرض ثابت (20/70/70/60).

**الحل:** نسب مئوية بدل بكسل، أو `table-auto`.

### ٥. شارات الأوزان في الإعدادات
٥ شارات × 70px = 350px + المسافات. **مش هتعدّي على 360.**

**الحل:** `flex-wrap` أو تصغير الشارة على الشاشات الصغيرة.

## Breakpoints

مشروعك موبايل أساساً، فمحتاج breakpoints قليلة:

```js
// tailwind.config.ts
screens: {
  'xs': '360px',   // أندرويد متوسط — الحالة الأهم
  'sm': '640px',   // موبايل كبير أفقي
  'md': '768px',   // تابلت
}
```

**الافتراضي (بدون prefix) = أصغر شاشة.** يعني اكتب الستايل للموبايل الصغير الأول، وبعدين زوّد للكبير:

```
text-sm xs:text-base
```

## الاختبار — مهم

**في المتصفح:** DevTools → جرّب على **320 · 360 · 390 · 430**.

**على تليفون حقيقي:** ده مش اختياري. خصوصاً:
- **تليفون الوالد نفسه** — هو المستخدم الأساسي
- **تليفون أندرويد رخيص** — ده اللي عملاؤك عليه

**نقطة مهمة:** المتصفح في الموبايل بياخد جزء من الشاشة (شريط العنوان). استخدم `dvh` بدل `vh`:
```
❌ h-screen   (بيحسب الشاشة كلها)
✅ min-h-dvh  (بيحسب المتاح فعلاً)
```

## الـ Safe Areas (الآيفون تحديداً)

الآيفونات الحديثة فيها "الخط" تحت (home indicator). الشريط السفلي بتاعك ممكن يتغطّى.

```css
padding-bottom: env(safe-area-inset-bottom);
```

وفي الـ HTML:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

## الخلاصة للتنفيذ

لما تدّي شاشة لـ Claude Code، ضيف السطر ده:

```
التصميم اتعمل على 393px، بس نفّذه responsive:
- يشتغل من 320px لحد 430px+
- استبدل العروض الثابتة بـ w-full داخل حاويات بـ padding
- الأزرار 44px تفضل ثابتة (مقاس اللمس)
- استخدم gap مش margins ثابتة
- min-h-dvh مش h-screen
```
